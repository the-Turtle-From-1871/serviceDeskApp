## Styling — Two Systems Coexist (read before touching CSS)
- **`globals.css` is the original design system** (the "property book" ledger look) and backs every pre-existing page via classes like `.card` / `.stack` / `.btn` / `.table`. It is NOT being migrated wholesale.
- **Tailwind v4 + `shadcn/ui` are for NEW UI only** (`src/components/ui/*`, the analytics dashboard). New work should prefer them; do not rewrite existing pages to Tailwind as a drive-by.
- `src/app/styles.css` is the entry point and makes the coexistence safe. Two rules keep it that way — **do not "simplify" either one**:
  - **Preflight is deliberately NOT imported.** Only Tailwind's `theme` + `utilities` layers are. Importing `tailwindcss` wholesale pulls in preflight and would restyle every existing page.
  - **`globals.css` is imported into a `legacy` cascade layer declared before Tailwind's layers**, so a utility beats a legacy rule of equal specificity. Unlayered CSS outranks *all* layered CSS, so without this every Tailwind utility would silently lose to `globals.css`.
  - **`@source` is narrowed to the two Tailwind directories, AND `@source not inline("container")` blocks that one candidate outright.** Narrowing alone proved insufficient: the extractor reads raw file *text*, so it harvested `container` from `data-slot="table-container"` **and from the English word in `table.tsx`'s prose comments**, generating a `.container` utility that outranked the `legacy` layer and widened *every* pre-existing page (720px → 1280px at a 1440px viewport, measured). Renaming the slot would not fix it — the comments regenerate it, as would the next person who types the word in these directories. Do not delete the exclusion; a Tailwind-native page wanting a centered cap should use `mx-auto max-w-*`. **The exclusion blocks a Tailwind `.container` UTILITY, not the CSS feature** — `globals.css` does use one real container query (`container-type: inline-size` + `100cqi` on `.card-more__fit`, the item card's Home unit), and it is unaffected: nothing in that path depends on a generated utility class. Do not read this exclusion as "container queries are banned".
- Because preflight is absent, `shadcn` primitives must set what preflight normally supplies: `appearance-none` + an explicit background/font on `<button>`-rooted parts, **`border-solid` wherever a `border-*` width is set** (Tailwind's border utilities set width only), and `[&_svg]:block` on icons.
  - **Corollary — a SINGLE-SIDE border needs the other three sides zeroed explicitly.** `border-solid` sets the style on all four sides, but `border-b`/`border-t`/`border-x` set a width on one. Preflight is what normally zeroes the rest; without it they keep the CSS initial width `medium` — **3px** — and the `solid` style makes them paint. So `border-b border-solid` draws a 3px box, not a 1px underline. Write `border-x-0 border-t-0 border-b border-solid border-border`. This bit `components/ui/table.tsx` (the analytics tables shipped a 3px frame); every other primitive pairs the all-sides `border` with `border-solid`, which is why they were unaffected. **Do not fix this class of bug with a global `border-width: 0` base reset** — that is preflight's border reset, and re-importing it piecemeal is what the section above exists to prevent.
- shadcn tokens are mapped onto the ledger palette in `styles.css` via `var()` references, so retuning `globals.css` retunes the dashboard. shadcn's `--primary` is aliased to `--primary-token` because `globals.css` already defines `--primary` (a self-reference would resolve to nothing).
- **A `<dialog>` must not carry a layout class — put the classes on an inner wrapper.** Browsers hide a closed dialog with the UA-stylesheet rule `dialog:not([open]) { display: none }`, and **any author rule that sets `display` beats it**. `.card` sets `display: block` and `.stack` sets `display: flex`, so `<dialog className="card stack">` makes every *closed* dialog render. That shipped once and was caught only in a real browser: `/items` had **50 closed dialogs**, one per row, each an absolutely-positioned 375×375 box, and a closed dialog's own `<p>` intercepted the pointer events that were meant to open it — the Delete buttons were unclickable. Write `<dialog ref={ref} style={{ padding: 0, border: "none", background: "transparent" }}><div className="card stack">…</div></dialog>`. **Do NOT fix this class of bug with a `dialog:not([open]) { display: none }` rule in `globals.css`** — that is a global override to work around markup one component owns, and it silently changes behaviour for every dialog added later. `src/components/DeleteItemButton.tsx` is the reference, and `ItemSelectTable.test.tsx` pins the invariant (the `<dialog>` has no `class`; the card is a child). It is still the only native `<dialog>` in the app and has no `::backdrop` rule of its own; the popover below does have one, so a second dialog should follow that lead rather than inventing a third treatment.
- **`[popover]` HAS THE SAME TRAP, for the same reason.** The UA hides a closed popover with `[popover]:not(:popover-open) { display: none }` — a type/attribute-selector rule any author `display` beats, exactly like the dialog rule above. So **the element carrying `popover` carries no layout class**, and nothing in `globals.css` may set `display` on it; layout lives on an inner wrapper. `src/components/SortFilterMenu.tsx` (the `/items` "Sort & filter" menu) is the reference and the only popover in the app so far; it is styled by id (`#items-sortfilter`) precisely so no shared class can grow a `display` later, and `ItemSelectTable.test.tsx` pins the same invariant it pins for the dialog. Also reset the rest of the UA popover box — `border: solid; padding: 0.25em; overflow: auto; inset: 0; margin: auto` — that last pair is what centres an unstyled popover in the viewport.
  - **What the Popover API buys, so nobody hand-rolls it again:** top layer (no ancestor `overflow` can clip the panel), Escape with focus returned to the invoker, click-outside dismissal, focus-order insertion, and — via `popovertarget` on the button — an implicit `aria-expanded`/`aria-details` pair. The `<details>`-based `.col-menu` (Columns, on both `/items` and the queue) has none of these; it works and is not being converted, but a NEW menu should be a popover.
  - **That `aria-expanded` is IMPLICIT — accessibility tree only, not a DOM attribute** — so `[aria-expanded="true"]` never matches in CSS. Read the open state off the popover instead: `.menu-trigger:has(+ [popover]:popover-open)`, which is why the panel must stay the trigger's immediate next sibling.
  - **The phone gets a bottom sheet and the desktop an anchored dropdown, and the nesting order of those gates is load-bearing.** Sheet rules are the unconditional base (`position: fixed; inset: auto 0 0 0`), needing no anchoring at all; the dropdown sits inside `@media (min-width: 721px)` **and** `@supports (anchor-name: --probe)`. CSS anchor positioning is Chrome/Edge 125, Firefox 147 and **Safari 26** — far newer than the Popover API's Safari 17 — so a device failing either gate keeps the sheet, and that IS the fallback: there is no second code path, and iOS never depends on anchor positioning. Do not "simplify" this by hoisting the anchored rules out of the `@supports`.
  - The sheet needs `env(safe-area-inset-bottom)` (home-screen install, no browser chrome beneath it) and `svh` rather than `vh` (the iOS URL bar). Its **`Done` button is sheet-only**, hidden inside the desktop block: a thumb has no Escape key and no obvious outside to tap, a mouse and keyboard have both. `Done` is a `<button popovertarget=… popovertargetaction="hide">` — no handler, no state.
  - **Cap the height on the PANEL, not the popover.** The popover element is reset to `overflow: visible`, so a `max-height` there spills instead of scrolling — and it cannot be made a flex/scroll container itself, because that would mean setting `display` on it.
  - **LIGHT DISMISS LETS THE CLICK THROUGH — you must spend that tap yourself.** The platform dismisses an `auto` popover on `pointerdown` and then delivers the `click` to whatever sits underneath, so a tap meant to close the menu ALSO pressed "Import CSV" / "+ Log new item" on `/items`. That shipped once. `useDismissSwallowsTap` in `SortFilterMenu.tsx` is the fix and the pattern to copy: decide at `pointerdown` (while `:popover-open` still answers truthfully, before the browser closes it), then `preventDefault` + `stopPropagation` the resulting click **in the capture phase**. `preventDefault` alone is not enough — it stops a link navigating but not a React `onClick`. Exclude the trigger (its own click is what toggles the panel shut) and clear the flag on `pointercancel`, or a drag that never becomes a click leaves it armed to eat some later, unrelated one. Same rule as `useRowGestures`: a tap that dismisses something is spent on the dismissal.
  - **The panel holds four native `<select>`s, not radio lists.** It shipped as 27 radio rows, which scrolled on a phone and pushed Direction and Then by below the fold; selects collapse it to four controls that fit without scrolling, and iOS gives the long unit list its wheel picker for free. Keep the panel's `max-height` + `overflow-y: auto` anyway — nothing guarantees the field list stays short, and an uncapped sheet grows off the top of the screen instead of scrolling.
  - **jsdom implements NO Popover API** — `showPopover` is undefined and `:popover-open` never matches — while it does apply the UA `display: none`. So a popover's contents are permanently hidden there: role queries need `hidden: true`, and opening, dismissal and focus behaviour are simply not testable in jsdom. `useDismissSwallowsTap` is INERT under jsdom for the same reason (it gates on `:popover-open`), so the click-through fix above has **no unit coverage at all** — verify it in a real browser, at both widths.
  - **Turbopack refuses a `node_modules` junction that points outside the project root** (`Symlink [project]/node_modules is invalid`), so a worktree parked beside the repo cannot run `npm run dev` off a junction to the main clone's modules. Vitest tolerates it; the dev server does not. Put agent worktrees under `.claude/worktrees/<name>` (gitignored) so the junction target stays inside the root, and remove the junction with `rmdir` — never a recursive delete, which follows it into the real `node_modules`.
- **Touch targets:** shadcn's stock sizes (32/36px) are below this app's documented 44px floor (`--tap`). The primitives carry `pointer-coarse:` + `max-md:` height overrides to restore it; if you add a component or override a height (e.g. `h-auto`), restore the floor explicitly or it ships as a ~22px tap target on a phone.
- **`--muted` is a SURFACE tint, not a text colour.** Muted *text* is `--text-muted` (`.subtle` uses it); `--text-subtle` is lighter still. `color: var(--muted)` looks plausible in the stylesheet and renders at **1.08:1** on the ledger surface — invisible, and neither `next build` nor jsdom will say a word. Measure contrast in the browser, as with any colour choice here.
- **Mobile navigation is a fixed bottom rail (`.nav-rail`), not a hamburger.** `AppHeader` renders BOTH the header nav and the rail at every width, and CSS alone (the 720px breakpoint) decides which is visible — there is no viewport check in JS, because a Server Component cannot do one and a client-side one flashes the wrong nav on first paint. Consequences to keep: the rail's height lives in `--nav-rail-h`, and `body:has(.nav-rail)` uses that same variable for the page's bottom clearance, so a rail that grows without the variable growing traps the footer underneath it; the rail carries `env(safe-area-inset-bottom)` because the app installs to the iOS home screen and has no browser chrome beneath it; it sits at `z-index: 40`, deliberately UNDER `.scan-sheet` (50) so the QR scanner covers it. Sign out is NOT in the rail — it is a card on `/account`, which is the only sign-out on a phone.
  - **`navItemsFor` feeds BOTH navs, so anything added there becomes a header link AND a tab.** Admin gets five — Search, Items, Queue, Users, Dashboard — and **five is the measured ceiling** (72px per tab at 375px, 61px at 320px, labels still intact); `nav.test.ts` pins the limit so a sixth forces a deliberate decision about what to drop. Queue and Users were folded into the Dashboard hub in `4dc1fe5` "so the header stays short" and were restored here because that constraint described a single-row header, not a rail. Dashboard remains the hub for Analytics, Categories, Units, Audit and New item.
  - **Account is deliberately NOT a nav item.** It is the `.profile-link` icon in the header's top-right at every width, so it never spends a tab and sits where it is looked for. `activeHref` therefore returns `null` on `/account` and the icon carries `aria-current` instead.
  - **Use `activeHref`, never `isActive` per item, to mark the current tab.** Queue and Users live inside `/admin`'s subtree, so `isActive` is true for both `/admin/queue` and `/admin` on the queue page — marking every match lights two tabs and puts `aria-current="page"` on two links, which is wrong for a screen reader, not merely untidy. `activeHref` picks the longest match, so `/admin/audit` still falls back to Dashboard. `isActive` keeps its subtree semantics on purpose; do not "fix" the overlap by narrowing it.
- **Below 720px a `.table--cards` row IS a card: tap to open, swipe left (or tap the pull tab) for actions.** Two tables opt in — `/items` (`ItemSelectTable`) and the service queue (`ServiceQueueTable`); everything else keeps the plain restacked row, because it has no per-row drawer and no single obvious destination for a tap. **The mechanism lives in `globals.css` + `useRowGestures` and is shared, so a third table opts in with a class and the three card cells — never a copy.** The queue differs only in its wiring: `longPressEnabled: false` (it has no bulk selection, so a 500ms timer on every touch would arm for no reachable outcome) and `swipeEnabled: true` unconditionally, since the whole route is behind `requireAdmin`. There is no second DOM and no viewport check in JS: under the breakpoint the shared rules have already made every `tr`/`td` a block/flex box, so `transform`, `position: absolute` and `overflow` behave as they would on divs, and the whole layout is CSS. Things to keep:
  - **The card is built from three cells of its OWN** (`.cell-serial` / `.cell-primary` / `.cell-meta`), while every data cell is hidden via `.cell-desktop`. Not a re-style of the data cells: those are rendered conditionally by the Columns menu, so hiding Serial would leave a card with no heading and — since the heading carries the link — no way to open the item at all. The corollary is intended: **the Columns menu shapes the desktop table only.**
  - **Tapping the card works through a stretched link** (`a.card-link::after { inset: 0 }`), not a click handler, so the accessibility tree sees one ordinary `href`. Anything that must stay tappable needs to sit above it on `z-index`. **Corollary: `a` must never be added to the pointerdown guard in `useRowGestures`.** The stretched `::after` covers the whole row, so *every* touch on a card reports an `<a>` as its target — matching on it refuses every gesture the feature exists for and silently kills swipe on both tables. That shipped for one round; jsdom cannot catch it (no hit-testing, so the target there is whatever the test names). The drawer's own links are inside `td.row-actions`, which the guard does match.
  - **The swipe hint is a pull tab at the card's right edge (`.swipe-grip`), not a chevron.** A chevron means *navigation* by iOS convention — which is what tapping the card already does — so the old `‹` argued with the gesture it advertised, and the More arrow now owns chevron-shaped marks on this card anyway. The tab is `position: absolute; top: 50%` against the `<tr>`, so it re-centres itself as the More panel grows the card; note that centres it on the **padding box**, which is right — the `border-bottom` is the ledger gap between cards, not part of the card.
  - **The tab is also a TAP target — it is a real `<button>` that opens the same drawer** (`toggleDrawer` in `useRowGestures`), because a swipe is undiscoverable to anyone who never tries one and a mark that advertises a gesture must not ignore the finger that reaches for it. It used to be an `aria-hidden` `<span>` with `pointer-events: none`; four things replaced that and each is load-bearing:
    - **`z-index: 3`, not 2.** Above the stretched card link (1) is only half of it: the tab is centred on the whole `<tr>`, so an expanded More panel grows the card and slides the tab down over `td.cell-more` — which is *also* `z-index: 2` and comes later in tree order, so at equal z-index it wins the tie and hit-tests on top. Measured at 390px with More open: the bottom **19px of the 44px tab** toggled the More panel instead of opening the drawer. It does **not** end up over the drawer, because `td.row-actions` is `z-index: 3` too and comes later still. **Growing the panel moves the tab further down, so re-measure when you add a row to it**: at six fields the 44px tab sits entirely over `td.cell-more` — 33px over the summary strip and **11px over the panel's first row** (measured at 390px, tab 503.8-547.8, list top 536.9). That is still fine, because `z-index: 3` means the tab keeps winning those taps and the panel's own content is not interactive — but a much taller panel would push the tab deep into readable rows, where a tap that opens the drawer stops being what the finger expected.
    - **`.swipe-grip` is excluded from the pointerdown guard in `useRowGestures`** (`button:not(.swipe-grip)`). The guard returns *before* a gesture exists, so without the exclusion pressing the tab and dragging would do nothing at all — dead precisely where a finger reaches for the gesture it advertises.
    - **The click handler spends `consumeSuppressedClick` first, with `holdSuppresses: false`.** A swipe that lifts off over the tab still synthesises a click there, and toggling on it would slam the drawer shut the instant the swipe opened it — that is the flag arm. The *hold* arm is opted out of: it exists so a hold can never NAVIGATE, and a tab that only toggles would otherwise do nothing at all when a press ran a beat past 500ms.
    - **`onPointerDown` must not spend the tap dismissing another row's drawer when the press starts on the tab** (`if (!onTab)`). Tapping any part of a *different* card while one is open is spent on the dismissal — right for an incidental tap, wrong for the tab, which is an explicit "show ME this row's actions": it made the tab need pressing twice whenever another row was open. **A test that fires a bare `click` cannot see this** — the dismissal lives in `onPointerDown` — which is exactly how it shipped past one round of tests; it was caught by CDP touch events at 390px.
    - **Preflight is absent, so the UA's button chrome survives** — `appearance: none`, `padding: 0` and an explicit background/border are what keep it looking like a tab rather than a system button.
    The visible tab stays 14px wide (any wider stops reading as an edge detail); the hit box is extended inward to 44×52 with a `::before`, reaching ~44px in from the card's right edge over padding and the tail of the meta row, where nothing else is interactive. **`/items` renders it on `isAdmin && !selecting` — the same condition `swipeEnabled` carries** — so it is present exactly when the drawer it opens is reachable; the queue renders it unconditionally, matching its own `swipeEnabled: true`. It needs no viewport guard of its own: `td.cell-meta` is `display: none` on the desktop table, so there is no width at which it can be pressed and nothing move.
  - **The "More" panel is a native `<details>`, and only `/items` has one.** It carries the six fields the card drops — Holder, Home unit, SLOC, Compliance, Last logon user, Last logon date — behind a full-width 44px chevron strip at the card's bottom edge. Native, so it opens before hydration and takes Enter/Space on the `<summary>` for free — no per-row state in a component that re-renders on every selection change. Its `<td>` needs `position: relative; z-index: 2` to sit above the stretched card link, or the tap navigates instead of expanding, and **`summary` must stay in `useRowGestures`' pointerdown guard** or pressing the chevron drags the card. Preflight is absent, so the UA's `display: list-item` marker survives: `list-style: none` plus BOTH `::-webkit-details-marker` and `::marker` are needed. The chevron is a lucide `ChevronDown` with `display: block`, not a `⌄` glyph — a text chevron is placed by font metrics and lands visibly above the label once rotated 180°. **The service queue deliberately has no More panel**: its card already shows all five of its columns, so the toggle would open onto nothing.
    - **SLOC is the one row that is CONDITIONAL — it renders only when the item has a storage location (trimmed).** Every other row stays put and shows a dash when empty, on purpose: a missing holder, home unit or last logon is itself a fact worth seeing, and rows that come and go make two cards impossible to compare at a glance. SLOC is the exception because most of the catalogue has none, so it would be a dash on nearly every card, between two rows that do say something.
    - **The panel's field list is NOT the desktop columns, and the two are allowed to differ.** UIC and Category are desktop columns that the panel deliberately does not repeat (make/model already imply the category, and Home unit says what the UIC says in words); Home unit, SLOC and the three MDM fields have no column at all and are otherwise reachable only by opening the item. Since the panel is fixed for everyone (the Columns menu cannot reach it), adding a field here costs every phone user a row — so add one because the phone needs it, not because the table has it.
    - **Home unit is font-sized to fit ONE line, in CSS, from a character count — not from a measurement.** `.card-more__fit` clamps `font-size` to `calc(100cqi / (var(--len) * 0.64))` between 9px and 13px, with `--len` set inline by `ItemSelectTable` and `100cqi` coming from the dd's own `container-type: inline-size`. **A JS measure-then-shrink cannot work here**: the panel sits inside a *closed* `<details>` until someone opens it, so there is nothing to measure on mount, and it would run per row on a 50-row list. Two details are load-bearing: the sized text must be a **span inside** the dd, because container units resolve against the nearest *ancestor* container and an element cannot size its own font from its own `cqi`; and nothing is set to `nowrap`, so a value too long even at 9px wraps honestly instead of being clipped. `0.64` is the glyph-width CEILING in em, measured in a browser across the catalogue's 18 real unit strings (0.52-0.63) — the ceiling rather than the mean on purpose, because erring high makes the text a touch small while erring low makes it overflow, and only one of those is visible as a bug. The cost is that a space-heavy name is charged more than it uses: the 53-character worst case measures 0.541em/char, so it renders at ~9.5px where ~11px would have fit. CSS cannot know a string's real width, so the safe bound is the price of doing this without JS.
  - **The select checkbox is VISUALLY hidden, not `display: none`.** `display: none` takes it out of the accessibility tree too, which would leave a 500ms touch long-press as the only way into selection mode — no screen-reader, switch-access or keyboard user could reach "Create receipt from N selected" or "Print QR codes" on a phone at all. It is clipped like `.sr-only` and gets a real 44px box on `:focus-within` or in selection mode. The visible rule is gated on `:has(input)` so a retired card — which renders the cell with no checkbox in it — does not get a 44px dead zone over the stretched link in its corner.
  - **A live drag is written straight to the row's DOM node, deliberately bypassing React** (`useRowGestures`' `onPointerMove`). As component state it re-rendered all 50 rows — each with its card cells and a full drawer including `DeleteItemButton` — on every pointer sample at up to 120Hz. `pointerup` settles the node to exactly the value React renders from `openId`, which is what keeps the two consistent: writing the resting value rather than clearing the property matters, because re-opening an already-open row renders no change and React would skip the style.
  - **Claiming the axis is not enough — a committed swipe must also `preventDefault()` the touch stream, from a `{ passive: false }` listener.** `touch-action: pan-y pinch-zoom` keeps vertical panning for the browser for the WHOLE touch, not just its opening samples, so the browser can still decide *after* the hook has locked the axis to `horizontal` that the same touch is a scroll — and it takes the pointer away with `pointercancel` to do it. Every cancel path in `useRowGestures` calls `settle()`, which restores the pre-gesture offset, so the card the user had already dragged 100px leftward sprang back to closed. That is the "it slides left and then goes back by itself while I'm scrolling" report, and it is a *touch-arbitration* bug, not a threshold one: `shouldOpen` never ran. The fix is the `claimTouch` effect in `useRowGestures` — a document-level `touchmove` listener that cancels the browser's default once `gesture.current.axis === "horizontal"`. Three things about it are load-bearing: **`{ passive: false }` is mandatory** (React attaches its own touch handlers passively at the root container, so an `onTouchMove` prop calling `preventDefault()` is silently a no-op and looks like it works); it relies on a `pointermove` dispatching completely **before** the matching `touchmove`, which is what lets the very sample that claims the swipe be the first one refused, while the event is still `cancelable`; and it is **single-finger only** (`e.touches.length !== 1`), because a second finger mid-swipe is a pinch and `touch-action` names `pinch-zoom` on purpose (WCAG 1.4.4) — without the count, every drag would quietly disable zoom for its duration. **Desktop Chromium cannot reproduce the bug** — it resolves the same arbitration before the axis is ever claimed, so all it can show you is the fix not regressing anything. Measured at 390px with CDP touch: pure-horizontal, 2:1 diagonal and shallow diagonal drags open with every touchmove cancelled (13/13, 13/13, 18/18); a 45° diagonal and a pure vertical drag scroll with **none** cancelled (0/13, 0/18); a second finger landing mid-swipe goes 0/12 while the first finger stays 4/4. Confirm the actual fix on a real iPhone — nothing local can.
  - **`--swipe-drawer-w` in `globals.css` and `DRAWER_WIDTH` in `components/swipe-row.ts` MUST stay equal** — the gesture clamps the card's travel to the constant, so drift either strands the card on bare background or hides the last button. It is 180px because it is sized against the *card* (356px at a 390px viewport), not against the labels; 216 was measured first and slid the device name and both badges off screen.
  - **The drawer cell must set `align-items: stretch` explicitly.** The shared mobile rule puts `align-items: baseline` on every `.table td` so a label and its value share a text baseline; inherited here it collapses the drawer's buttons to the height of their own text (20px measured, in a 141px card).
  - **`.actions > :not(dialog)` — the `:not()` is load-bearing.** `DeleteItemButton` renders its `<dialog>` as a sibling of its button, so a bare `> *` sets `display` on a closed dialog and re-creates the closed-`<dialog>` bug above. Note also that `:not()` takes its argument's specificity, so that selector scores (0,3,2) and beats a three-class rule — which is why hiding the drawer's View link needs the child combinator.
  - **Both `:hover` rules exist because hover STICKS on touch.** The row and the card link each neutralise it; without them the last card you tapped stays tinted and its serial stays underlined.
  - Long-press (500ms) enters selection mode, which is **derived from `selected.size`, not its own state**; swipe is disabled while selecting, and both gestures ignore `pointerType === "mouse"`, which is why neither needs a viewport check. Gesture arithmetic is pure and unit-tested in `swipe-row.ts`; the pointer/timer wiring is in `useRowGestures.ts`.
  - **The card link must keep `-webkit-user-drag: none` AND `draggable={false}`, or the iOS long press opens the item.** A held `<a href>` is a *draggable link* on iOS: the system drag gesture claims the touch and WebKit fires `pointercancel`, which kills the 500ms timer — so the lift is just a tap and the card navigates instead of selecting. `-webkit-touch-callout` suppresses the *preview sheet* but NOT the drag, so it is not enough on its own. `-webkit-user-drag` does not inherit, so it sits on `.card-link`, not the row. **This reproduces on a device only**: synthetic pointer events suppress correctly in both Chromium AND WebKit, so the unit test pins the fail-safe below instead of the cause. **Confirmed fixed on a real iPhone (2026-08-07)** — the properties are load-bearing, not a guess, so do not drop them on the grounds that no local test exercises them.
  - **`consumeSuppressedClick` also refuses a click that ends a press ≥ `LONG_PRESS_MS`, from `lastPress` — a ref kept OUTSIDE the gesture slot so it survives `endGesture()`.** This is the fail-safe for exactly the takeover above: if anything ever cancels the pointer stream mid-hold, a deliberate press still cannot navigate. It is gated on `longPressEnabled`, so the queue — where a long press means nothing — still opens the item on a slow tap.
  - **The card row must keep `-webkit-touch-callout: none` + `user-select: none`.** The card is a stretched `<a>` and the long press fires at 500ms — precisely when the OS claims the same press on the same element: iOS raises the link callout/preview sheet, so selection mode switches on and vibrates *underneath* a system sheet, and Android starts a text-selection drag whose handles then swallow the swipe. Both properties inherit, so they sit on the `tr` and cover the link and the card text. The tradeoff is deliberate — long-press is the app's selection gesture, so that text cannot also be the browser's — and it is scoped to the card layout, leaving the desktop table selectable. **Neither symptom reproduces in desktop Chromium**, which is why this is written down rather than left to be re-discovered on a phone.
  - **`useRowGestures` takes `rowIds` and drops the open drawer when that set changes.** Both tables stay MOUNTED while their rows change beneath them — `/items` pages and sorts via `router.push` inside the same route, and the queue filters and sorts client-side — so without this, swiping a row open, paging away and coming back re-mounts it already slid aside from a gesture nobody made on this visit. Compared by CONTENT (`join(",")`), never array identity: `rowIds` is a fresh array each render, so an identity check would slam the drawer shut on the very re-render that opening it causes. It is a guarded render-time write (React's "adjust state when a prop changes"), not a `useEffect`, so the drawer never paints open for a frame first.
  - **The one-gesture-at-a-time guard needs the document-level rescue listener to stay.** `gesture.current` is a single slot and `onPointerDown` returns early while it is full, which is what stops a second finger hijacking a live swipe — but every row handler that could empty it first requires `g.rowId === rowId && g.pointerId === e.pointerId`, so a pointerup landing anywhere else (row unmounted mid-drag, pointer capture lost, a fling lifting off over another card) leaves the slot occupied and refuses **every** later swipe and long-press on the page until a remount. The `pointerup`/`pointercancel` listeners on `document` fire after React's root-container handlers, so they are a no-op for ordinary gestures and only ever clean up the ones a row missed — treated as cancelled, not guessed into an open/close.
- **`npm run build` and jsdom are NOT evidence for a CSS change.** Neither has a layout engine. Verify visual work in a real browser. Every measurement quoted in the rule above came from driving a 390×844 Chromium with real touch and keyboard input; jsdom reported none of those bugs, and one of them (a broken comment) only surfaced after clearing `.next` — **Turbopack caches a CSS syntax error across a dev-server restart**, so a 500 that outlives your fix means `rm -rf .next`, not a wrong fix.
